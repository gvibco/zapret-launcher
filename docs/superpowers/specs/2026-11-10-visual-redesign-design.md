# Zapret Launcher — визуальный редизайн и оптимизация

Дата: 2026-11-10
Статус: согласовано с пользователем, реализуется

## 1. Контекст

Лаунчер функционально готов, но использует дефолтные контролы WPF: белые ComboBox с белым
текстом, обрезанные подписи CheckBox, системный синий хайлайт в навигации, красный текст на
тёмном фоне. Интерфейс выглядит техническим прототипом, а не продуктом.

Дополнительно процесс занимает ~285 МБ working set / ~172 МБ private bytes после долгой
работы. Основные источники: перестройка коллекции логов на каждую строку winws, буферизация
всего zip-архива обновления в памяти, меню трея, создаваемое целиком на старте, и отсутствие
возврата памяти при сворачивании в трей.

## 2. Цели

1. Единая визуальная система для всех шести экранов: статус, стратегии, покрытие, проверка,
   настройки, логи.
2. Читаемость: контраст текста не ниже 4.5:1, отсутствие обрезанных подписей, видимый фокус.
3. Более «продающий» вид: выраженная иерархия, крупное главное действие, цветовые статусы.
4. Снизить потребление памяти и фоновую нагрузку без изменения функциональности.

Не-цели: новые функции, изменение бизнес-логики, смена библиотек, установщик.

## 3. Визуальное направление «Сигнал»

Продукт — премиальный локальный сетевой инструмент. Один запоминающийся элемент: живой
статус-бейдж с пульсирующей точкой, когда обход включён. Остальное сдержанно.

### Типографика

- `Segoe UI Variable Display`, fallback `Segoe UI`.
- Заголовок страницы 26 px semibold, подзаголовок 13 px, заголовок секции 15 px semibold,
  тело 13 px, метаданные 12 px.
- `Cascadia Mono` для аргументов winws и логов.
- Без ALL CAPS, без типографических «рекламных» надзаголовков.

### Форма и композиция

- Сайдбар 236 px: логотип-щит, название, подпись «Обход блокировок», пункты с линейными
  иконками, активный пункт — акцентный пилл с левой полосой.
- Hero-карточка статуса: радиус 16, тонкая градиентная рамка, крупная кнопка действия.
- Секции: плоские карточки радиуса 12 с бордером, без одинаковых теней.
- Поля и кнопки: радиус 9–10. Кнопки: primary (градиент), secondary (поверхность), ghost
  (прозрачная), danger (красная).
- Один мягкий радиальный ореол в правом верхнем углу контента, не перекрывает текст.

### Статусы

- Успех: зелёная точка/плашка на `#3DDC97`.
- Предупреждение: янтарная плашка.
- Ошибка: красная.
- Неизвестно: приглушённый текст.

## 4. Экраны

### Статус

Hero: бейдж состояния, имя стратегии, метаданные (движок, сеть, права), главная кнопка
включения/выключения. Ниже три метрики YouTube / Discord / Google с цветом по результату.
Кнопки проверки и теста. Блок предупреждений; при их отсутствии — зелёная плашка «Всё в порядке».

### Стратегии

Слева список стратегий с режимами и цветным счётом, справа карточка выбранной: имя, режимы,
счёт, время теста, primary-кнопка запуска, аргументы winws в моноширинном блоке, копирование.
Прогресс теста — отдельная строка внизу.

### Покрытие

Заголовок с кнопкой обновления списков. Карточки: источники, свои домены, исключения,
свои IP/подсети, IPSet Filter, Game Filter с кнопкой «Применить». Списки — строки с иконкой
удаления; предупреждения — янтарные плашки.

### Проверка

Две карточки: «Проверки» и «Сайты». Статусы — цветные точки и подписи. Кнопки запуска и
копирования отчёта. Итог — строка состояния.

### Настройки

Карточки: поведение (переключатели), цели проверки, движок, данные приложения, примечание
про WinDivert. Опасное действие «Сбросить настройки» — danger-кнопка.

### Логи

Панель фильтра и действий, ниже тёмная моноширинная поверхность с виртуализированным списком.

## 5. Реализация

- `Themes/Dark.xaml`, `Themes/Light.xaml` — только цветовые токены и градиенты.
- `Themes/Controls.xaml` — кастомные шаблоны Button, TextBox, ComboBox, CheckBox,
  ToggleSwitch, ScrollBar, ListBox, ListBoxItem, карточек, иконок и типографики.
- `Themes/Icons.xaml` — линейные векторные иконки (PathGeometry).
- `App.xaml` подключает палитру и контролы; `ThemeService` заменяет только палитру.
- Собственная панель заголовка на `WindowChrome`: перетаскивание, двойной клик, кнопки
  свернуть/развернуть/закрыть; при развороте окно ограничивается рабочей областью монитора,
  чтобы не уходить под панель задач.
- Контент страниц ограничен шириной 1120 px и центрируется на широких экранах.
- Конвертеры: результат проверки → кисть, счёт стратегии → кисть, статус диагностики → кисть,
  пустая строка → Visibility.
- Логика приложения и биндинги сохраняются.

## 6. Оптимизация памяти и нагрузки

1. `LogsViewModel`: строки winws копятся в очереди и применяются пакетом раз в 250 мс;
   при пустом фильтре добавляются только новые строки. Коллекция ограничена 1000 строк.
2. `UpdateService`: архив обновления скачивается во временный файл и распаковывается потоком,
   без `MemoryStream` на весь архив.
3. `TrayService`: пункты меню стратегий создаются при первом открытии меню.
4. `MainWindow`: при сворачивании/скрытии в трей вызывается компактная очистка и
   `SetProcessWorkingSetSize`, чтобы вернуть неиспользуемые страницы ОС.
5. `LogService`: постоянный буферизованный writer вместо открытия файла на каждую строку.
6. Проект: workstation, non-concurrent GC для меньшего футпринта.
